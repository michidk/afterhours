# AFTERHOURS development

Keep gameplay authoritative in `server/`. Browser movement prediction is provisional and must reconcile with server snapshots; it must never decide final positions, damage, pickups, or ownership. Keep reusable movement and data contracts in `shared/`. Cities are generated by the pipeline in `mapgen/` and `scripts/`. Every server boot regenerates the versioned artifact and its baked meshes (`scripts/prepare-city.ts`, run as a separate process), replaces the files on disk, then loads them; `CITY_REGENERATE=0` serves the files already there. Never generate a city inside the server process. Clients receive the loaded city from the server.

Run `bun run test` and `bun run build` after gameplay or protocol changes. Update README controls and limitations when behaviour changes. Production debug tools must remain explicitly opt-in.

Use Conventional Commits: `<type>(<optional scope>): <description>`. Allowed types: feat, fix, docs, style, refactor, perf, test, build, ci, chore, revert. Use an imperative lowercase description, no trailing period, and a subject at most 72 characters. Mark breaking changes with `!` and/or a `BREAKING CHANGE:` footer. Add a body when the reason is not obvious; keep trailers last. Applies to amends, squashes, and reverts too.
