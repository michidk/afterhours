# Live lag check, 2026-10-19

Lag remains reproducible on production image `73411f2`. The test used five
independent clients per phase, ten seconds of warmup and sixty seconds of
measurement. No artificial network delay was added. A temporary Node DNS preload
selected `178.162.254.45` for `afterhours.k8s.lohr.dev`, retaining the hostname,
HTTPS certificate validation and WebSocket origin.

| Phase   | Passing clients | Largest correction               | Observation                                                                                                   |
| ------- | --------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Walking | 5/5             | 0.033 m                          | All clients sustained movement.                                                                               |
| Cars    | 1/5             | 1.902 m                          | All sustained movement; four exceeded the 0.3 m correction threshold.                                         |
| Planes  | 0/5             | 19.981 m among sustained flights | Only two sustained flight; both had corrections near 20 m. Three failed flight or lost their controlled body. |

The failed-flight clients include a 545 m correction. That is not a clean
measurement of network lag because failed flight and respawn can also relocate
a player.

Five-second health polling during each measured window found:

| Phase   | Highest reported tick p95 | Worst reported tick | Additional dropped simulation time |
| ------- | ------------------------- | ------------------- | ---------------------------------- |
| Walking | 32.0 ms                   | 96.3 ms             | 0 ms                               |
| Cars    | 40.0 ms                   | 199.0 ms            | 0 ms                               |
| Planes  | 49.7 ms                   | 266.1 ms            | 287 ms                             |

The tick budget is 33.3 ms. Health percentiles cover the server's rolling sample
window and are not limited exactly to each phase. The server was under tick
pressure during the vehicle phases; this run does not establish the precise
cause of every correction.

This is one run per phase. The load generator shared a busy machine with other
builds and the local test suite. Its worst recorded input scheduling delays
were 172 ms walking, 149 ms driving and 245 ms flying. These delays remain a
confounder even though none crossed the harness's 250 ms failure threshold.
The clients run real prediction, input clocks and rendering interpolation, but
this harness does not measure browser GPU rendering or the player's own ISP.

An earlier walking-only check through the public main-node route also failed
and was stopped before the car phase completed. It is not a complete second
three-phase run or a controlled routing benchmark.

[Per-client report](lag-check-2026-10-19.json) contains the acceptance failures,
movement and airborne fractions, snapshot age, input age, scheduling delays and
corrections. Raw client telemetry remains under the report's temporary artifact
directory in this workspace.
