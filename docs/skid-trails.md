# Detailed tyre trails and map streaming

The enlarged city stretched each old 512 px skid texture across 408 m. A 0.26 m tyre occupied about 0.33 pixels, making rubber almost disappear. The replacement atlas keeps 1024 px per 64 m world tile: 16 px/m, or approximately four pixels across a tyre, independently of map bounds. Tiles allocate only where marks exist; sixteen resident textures cap their cost.

The trails use rounded translucent rubber bands and narrow tread grooves. Their positions match the visible car wheel mounts, including sedan/sport/van width and length scaling and yaw. Street tiles clear the road paint; airfield tiles also clear the raised runway markings. Trails sample rendered poses and provisional wheel slip, so local rubber does not wait for server events. New marks upload in the same frame; fading remains batched. Marks expire after 40 seconds, with an 8,000-mark safety cap. Offscreen GPU meshes, materials and textures dispose; unexpired CPU marks can repaint when the camera returns.

Verification on 2026-10-11:

- Unit regressions cover far positive/negative coordinates, tile seams, constant resolution, groove painting, immediate slip samples, airborne/teleport resets, refresh-independent distance sampling, and scaled/rotated wheel mounts.
- A native browser component check at (780, -780) uploaded a new mark during a 1/165-second update. Twenty-five marked tiles retained sixteen GPU textures; moving focus away released all tile meshes/textures, returning repainted sixteen, and advancing through expiry released them again. Only Babylon's shared default material remained.
- The built production client with explicitly enabled development commands drove a server-owned Comet GT at the airfield. After accelerating to 22.28 m/s, a 1.3-second right/handbrake turn activated both rear slip flags, emitted eight marks and made four uploads. Subsequent render samples brought the total to sixteen marks. The real rubber is visible in the [browser screenshot](screenshots/skid-trails-night.png). Slow software rendering produces fewer sampled points than a hardware client; this is functional evidence, not a GPU performance measurement.
- The saved-map streaming suite covers stable map identities, reconstruction across overlapping chunks, neighborhood-only downloads, seam deduplication, eviction, player collision retention during free-camera movement, late-response cancellation, download retry/backoff, wrong-map rejection, and complete offscreen server simulation. A Babylon NullEngine regression verifies synchronous mesh capture/batching and actual disposal, despite deferred mesh-added notifications.
- `bun run check`, `bun run test` (97 tests including map/sprint additions), and `bun run build` pass. Concurrent test servers use OS-assigned ports so independent agent test runs do not collide.

The server retains the entire manually generated artifact in memory and continues all simulation. Browser geometry is server-delivered, held only in an active chunk cache, and unloaded when distant. The debug camera retains the player's collision neighborhood while loading its own view. See [architecture](architecture.md) for the transport and resource ownership.
