# Movement lag investigation, 2026-10-19

The acceptance limits remain unchanged: five independent clients in each of
walking, driving and flight, ten seconds of acceleration followed by sixty
measured seconds. Every client must sustain movement, and planes must sustain
flight. Corrections over 0.3 m, snapshots over 300 ms old, acknowledged inputs
over 400 ms old, missing samples and simulation below 90% of wall time fail.

## Fixes

- Chunk JSON parsing and schema validation run in a worker. Meshes transfer as
  typed buffers instead of copying large JavaScript number arrays between
  threads. The live bot uses the same decoder in a Node worker.
- Loading duplicate chunk edges preserves collision-array identity and its
  spatial cache. The streaming download queue sorts missing chunks only.
- Input queues retain commands for simulation ticks the runtime still owes.
  A returning batch no longer loses those commands before catch-up runs.
- Presentation advances its sequence and timestamp anchor when authority has
  acknowledged slots simulated with held controls. Without that update, the
  next snapshot could correct a full tick of movement. The focused reproduction
  measured 1.733 m for a car and 1.333 m for a plane before this fix.

The bot now measures actual input-pump gaps. Resetting its scheduling clock after
a long gap previously concealed stalls in the load generator. CPU profiling is
available through `scripts/five-client-test.ts --profile`; profiled runs are
diagnostics, not acceptance results.

## Verification record

  passed all fifteen clients on commit `0b7d55f`, with sixty measured seconds per
  phase. The largest correction was 0.0015 m, snapshot age 100.8 ms and applied
  input age 222.8 ms. All cars sustained movement and all planes sustained flight.
  Simulation stayed within 0.1% of real time. This is one run on a four-core
  runner against a local server, not a production routing or browser result.
  [The per-client report](lag-fixed-clean-runner.json) retains the exact values.
- The clean commit's unit suite, type checks, formatting, architecture checks and
  production build passed in [CI](https://github.com/michidk/afterhours/actions/runs/39272913299).
  The downstream image, network and browser jobs were canceled by the next push.
- [The independent production baseline](https://github.com/michidk/afterhours/actions/runs/39271930932)
  failed every phase. It predates deployment of the queue fix and the held-input
  presentation fix. Car corrections were about 0.317 m; input-age maxima were
  422–532 ms across phases. One plane failed takeoff and remains a failed client.
- The patched local run `/tmp/lag-five-held-fixed.json` passed all five walking
  clients. All five cars sustained movement and all five planes sustained flight,
  but those phases failed the timing gates. Simulation ran at 45% and 79% of wall
  time respectively. Car input age reached 1.745 s and plane input age 1.275 s.
  The workspace simultaneously hosted unrelated compilation and rendering jobs;
  its load average was 29 on twelve available logical CPUs, with a nine-core
  container quota. These are failed acceptance results, not proof of a fix.

The manual **Live movement acceptance** workflow supports `local`, `direct` and
`public` routes. `local` builds and boots the checked-out server on the independent
runner. `direct` preserves the production HTTPS hostname while resolving it to
the game node. `public` uses normal DNS. Raw client traces and the aggregate
report are uploaded even on failure. The local route also uploads server logs.

This test exercises real networking, prediction, streaming and presentation
physics. It does not measure WebGL frame pacing or the user's ISP connection.
