# Architecture

The city artifact is immutable during a server process. `scripts/generate-city.ts` is the only production generation entry point. It runs the `mapgen/` pipeline, converts the result with `scripts/mapgen-city.ts`, accepts `--seed` and `--out`, validates output, and writes `{format:"afterhours-city", version:5, city:{...}}`. Version 5 adds `centre` (the downtown reference used for spawn sites), `surface` (street polygons with profile heights, served in the manifest and drawn instead of per-segment road boxes), building `y` and `angle` (pad altitude and footprint rotation; `h` stays the absolute roof altitude so roof physics is unchanged), and an 8 m terrain grid. Street fixtures, parks, the airport and pickups take their altitude from that terrain. The checked-in artifact is deployment input, not a client asset. Buildings include bounding dimensions, roof heights, colours, facade styles, replaceable asset IDs and quarter-turn street-facing orientation; palms/lamps include server-visible positions/heights. Saved-city schema changes require an explicit artifact format version change and migration. Network-only gameplay changes do not change the city artifact.

`server/city-loader.ts` reads `CITY_PATH` (default `data/city.json`), parses JSON and applies the Zod artifact schema. `Simulation` requires an explicit City; there is no runtime generation fallback. The CPU server simulates the complete map regardless of connected clients or their visible neighborhoods. Only restarting with another artifact replaces the map.

`server/city-stream.ts` indexes that loaded artifact once into 128 m chunks. `/city` and the versioned welcome contain a manifest with SHA-256 map identity, seed, bounds, chunk size, airfield descriptor and the saved 97 × 97 terrain height grid. Terrain is available before prediction starts. Shared triangle interpolation matches the rendered mesh and the Rapier debris collider. `/city/chunks/<mapId>/<x>/<z>` sends static geometry for one region; mismatched map identities return 409. Objects overlapping neighboring chunks share original artifact array IDs. Dynamic entities/pickups continue through the existing snapshot interest system. Neither generation code nor the artifact is bundled in the client. Map requests use `no-store`; clients keep geometry only in active memory.

`client/world/stream.ts` limits concurrent downloads to four and prioritizes the player collision area before camera scenery and outer prefetch. Prediction requires all chunks within `TUNING.interestRadius + 32` metres of its position, currently 252 m, so geometry extends beyond the 220 m snapshot interest and local physics queries. Downloads prefetch another 128 m chunk of margin, currently 380 m. Collision arrays include this entire resident cache, while `CityRenderer` receives only camera-visible chunks. The player collision area remains loaded even when the debug camera travels elsewhere. Input prediction, pending-input replay, and display extrapolation fall back to authoritative/interpolated poses when required chunks are missing, including after teleportation or if prediction moves beyond coverage. Requests cancel when no longer needed, chunk identities are validated, failures retry, and distant data is evicted. Partial-city array identities change when resident geometry changes so shared collision caches invalidate. Zooming out expands camera interest without changing server simulation.

The first loading screen stays visible and the entry form stays inert while the client downloads the manifest, initializes WebGL, downloads spawn scenery within 252 m, and prepares the first rendered frame. The outer collision prefetch ring and camera streaming begin after joining. The entry form then appears ready to enter, without a second scenery-loading screen or a percentage bar. Manifest download, spawn preparation, and render readiness each have a 30-second timeout; a failed startup keeps an error visible on the first screen.

The M map uses a separate on-demand `/city/atlas/<mapId>` navigation overview prepared from the same loaded artifact. It contains road endpoints/widths, parks, landmarks and ramps, not full collision or building data. `client/ui/city-map.ts` validates/caches that overview in active memory and draws live snapshot markers with an independent pan/zoom transform. Opening it releases gameplay controls and leaves 3D chunk interest unchanged. See [controls and verification](map-controls.md).

`client/world/render.ts` owns meshes for stable feature IDs, draws boundary objects once, and disposes evicted mesh/shadow/light/sign-texture resources. Roads and signals build only for loaded chunks; airfield geometry loads when a visible chunk intersects its bounds. The terrain mesh and ocean are global. Shared palette materials remain reusable. Babylon's mesh-added notifications are deferred, so resource ownership captures mesh differences synchronously before/after batching.

Tyre trails use a separate sparse atlas: 1024 px per 64 m tile gives 16 px/m regardless of world size. Rounded translucent rubber bands and grooves follow displayed wheel mounts and predicted slip. New marks upload in the current render frame; fading is batched every 200 ms. At most sixteen nearby textures and 8,000 CPU marks survive, with a 40-second lifetime; GPU tiles are disposed offscreen and surviving marks can repaint on return. Trails are cosmetic and are not saved or sent by the server.

| Layer           | Modules and ownership                                                                                                                                                                               |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Offline tooling | City generator, physics evaluation, capacity benchmark, dependency checks                                                                                                                           |
| Shared          | Entity/input/city types; versioned protocol; Zod input validation; catalogs; MessagePack codec; grid/graphs; movement/contact functions                                                             |
| Server          | HTTP and artifact loader; Sessions transport/rate/ownership checks; Runtime fixed scheduler; Simulation world outcomes; CityAI routes; Combat history/hits; Inventory items; lifecycle spawn safety |
| Client          | Main composition and HUD updates; UI layout; Controls; GameNetwork snapshots/reconnect; Prediction replay; CityScene art; Effects; Camera; GameAudio                                                |

The shared movement code changes kinematics only. Prediction never applies damage, grants inventory, picks ownership, plays duplicate server events, or spawns entities. An authoritative snapshot replaces the physical predicted body and pending inputs are replayed; a short render-only error offset reduces visible corrections. Large corrections and ownership changes reset that offset/history. Floating-point trig is not assumed bit-identical on all platforms.

`shared/destruction.ts` derives stable runtime fixtures and holds collision masks outside immutable city data. `server/destruction.ts` owns their damage, Rapier 3D debris, corpse bodies, expiry and safe restoration. Reliable membership updates and spatial debris snapshots drive `client/world/destruction.ts`; its separate models can move/fade without changing batched roads/buildings. Driving retains the planar vehicle solver. [Lifetime and implementation scope](destruction.md).

Connected-player rosters are separate from spatial entity interest and reconnect ghosts. Sessions sends names/colours/IDs when membership changes; the top-left player list sorts the local player first and uses text nodes for names.

Vehicle capacities live in `shared/catalog.ts`. Each server-spawned vehicle carries a fixed-length `seats` array of occupant IDs/null slots; slot zero agrees with `driver`. Occupants carry `vehicle` and `seat`, assigned only by `Simulation.interact`. Boarding chooses the first vacancy, so a freed driver seat can be claimed without changing existing passengers' roles. Only the driver/pilot's input reaches vehicle physics; passenger inputs are ignored for movement. Passengers use the interpolated vehicle pose without a predicted body or pending movement replay, and the local passenger pose follows that same render pose. Exit/disconnect releases only the departing seat; explosions eject and damage all occupants. A helicopter has a shared one-second boarding countdown before lift, extended to at least half a second by a new passenger; pilot movement skips it. Server and prediction run the same countdown.

Server input queues retain two frames, consume one per 30 Hz tick, reject stale sequences, and release held controls after 250 ms without input. Overflow sheds the oldest input so newer stops and turns survive. Snapshots acknowledge the last applied frame; older discarded frames also leave client history. WebSocket delivery is ordered/reliable; `base` mismatches request a full snapshot. Full recovery also occurs every two seconds. Interest removal deletes local render nodes; reconnect resets snapshots and sequence history.

The custom contact system uses oriented rectangles, three impulse/penetration passes, spatial broadphase, and 120 Hz substeps. Static geometry cache is shared with prediction. Height filters separate airborne entities from street traffic. Weapons query actual footprints and walls, with bounded pose history owned by Combat. Server events feed bounded cosmetic rendering/audio.

Airborne aircraft exit is a server-owned ownership transition: the player retains altitude, receives parachute state, and separates beyond the aircraft footprint. Shared character movement handles steerable descent, roof/ground support, and canopy removal on touchdown; prediction runs those same kinematics. Abandoned aircraft retain horizontal momentum and fall under gravity; the shared movement helper reports impact speed, and only the server applies damage and emits impact/fire/explosion events. Disconnect releases ownership immediately while preserving the player for the reconnect window.

Distant remote snapshots feed a continuous delayed render clock and velocity-aware interpolation. Nearby contacts render from the same provisional world as the controlled body, blending back to interpolation between 12 and 24 m. Local rendering predicts the fraction between input ticks without mutating replay state. Pending simulation beyond 250 ms falls back to authority until acknowledgements catch up. See [networking research and verification](networking.md). Render models consume those poses directly. Recorded CC0 WAVs are local browser assets, with source/license provenance in `public/audio/CREDITS.md`; `scripts/prepare-audio.ts` performs offline normalization and loop editing. No audio generation or FFmpeg is part of runtime simulation.

Boundary checks disallow client↔server dependencies, Node APIs in the browser/shared layer, and rendering dependencies on the server/shared layer. `scripts/` may import runtime modules for test/benchmark fixtures; runtime modules must not import city generation tools.

`mapgen/` is the next-generation map pipeline: pure TypeScript with no Node or Babylon imports, so the same code runs in the offline `scripts/mapgen-stats.ts` run and in the `explorer/` Web Worker. Stages are terrain, erosion, hydrology, site, roads, road geometry and terrain stamping, blocks, buildings, vegetation; each consumes only earlier outputs and derives its own seeded random stream, so one stage can be rewritten without reshuffling the others. `explorer/` is a separate Vite root (`vite.explorer.config.ts`, port 5180, output `dist-explorer/`) and is never part of the game bundle. The game still loads the v4 artifact; [city generation research](city-generation-research.md) records the algorithms and the integration steps toward a v5 artifact.

`shared/debug.ts` defines validated, correlated debug commands; `server/debug.ts` executes them against authoritative simulation state. Sessions gate commands and camera-interest overrides on the server's debug setting. `scripts/agent-client.ts` sends ordinary sequenced gameplay input and debug requests for repeatable scenarios. `client/debug/` exposes the browser controller only after a debug-enabled welcome. Debug state is cloned for inspection; mutations never bypass server simulation. Reconnect-token takeover removes the previous transport immediately, preventing an old socket's delayed close from losing the restored session or inflating player counts.

`client/camera/debug.ts` owns independent camera poses and movement math. Main composition sends idle gameplay inputs while a debug camera is active, and a bounded debug-view message moves only snapshot interest. `client/lighting/environment.ts` maps authoritative time to continuous environment parameters; `client/lighting/index.ts` applies sky, sunlight/moonlight, ambient colours, fog, shared emissive windows, ground-light pools on every loaded intact streetlamp, and four pooled local lamp lights. Lamp pools belong to destructible fixture roots so breaking, restoring, and unloading a lamp also affects its light. Scenery streams over a minimum 512 m radius, including during startup, independently of dynamic-entity interest. The client advances visual time using the received server clock rate and corrects it from snapshots. See [debugging](debugging.md) for commands and visual evidence.

`server/traffic.ts` samples progress and stationary-car clusters once per second, selects only unoccupied AI cars from persistent gridlock, and paces removal/replacement separately from `CityAI` steering recovery. Replacements use lane-aligned `CityAI.assignCar` routes and validated clear road sites away from players. Simulation rebuilds spatial interest after traffic mutations so despawns cannot leak into the same tick's snapshot. Wreck replacement shares this delayed safe-spawn path. Traffic diagnostics appear in health/debug state; [traffic details and evidence](traffic.md).

The v4 island uses shared `LIMIT = 1536` and persisted road segments: a compact downtown grid, curved coastal routes, radial avenues, loops and dead ends. The saved island has a seed-dependent irregular coast, a level urban plateau and rural hills up to 171 m for seed 713. The outer `WORLD_LIMIT = 1792` boundary constrains full vehicle footprints at every altitude; boats and cars also resolve against the terrain shoreline. The offline generator splits intersections and places frontage buildings with road and sidewalk clearance. Rendering, chunk bounds, minimaps, traffic and pedestrian navigation derive from those same segments; diagonal lanes use normalized perpendicular offsets. Sidewalks connect segment endpoints around each junction. Parks carry dimensions and garden/civic/woodland treatments. The server spawns the plane relative to the loaded airfield. Tree props participate in shared collision and aircraft clearance. Ambient population remains bounded. The optional offline atlas is generated with `--preview`; neither its code nor city-generation code enters a runtime bundle.
